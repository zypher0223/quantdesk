# QuantDesk Web

React 19 + TypeScript + Tailwind CSS v4 前端，数据全部来自本地只读行情网关。

## 启动

```bash
npm install
npm run dev        # http://localhost:4173
```

Vite 只监听 IPv6 的 `localhost`，用 `http://127.0.0.1:4173` 会连接被拒。

先在另一个终端启动网关（见 `../engine/README.md`）：

```bash
cd "../engine"
QUANTDESK_PROXY=http://127.0.0.1:12003 .venv/bin/python -m quantdesk.cli serve
```

`QUANTDESK_PROXY` 只在需要代理时设置；代理地址也可写入 `~/.quantdesk/config.toml` 的 `[proxy] url`，环境变量优先。本机直连 `api.bybit.com` 会被拒（TCP 超时），所以这里通常必须配代理。

## 代理路径

`vite.config.ts` 把三类请求转发到 `127.0.0.1:8765`，缺一条都会让请求打到 Vite 自己并变成 404：

| 路径 | 用途 |
| --- | --- |
| `/bybit/*` | 原始 Bybit 只读行情（kline、tickers） |
| `/api/*` | 引擎计算面板（合约池、合约状态、共振） |
| `/health` | 网关健康与代理配置状态 |

**不要**在没有 `--config vite.config.ts` 的情况下调用 vite：目录里一旦出现 `vite.config.js`，vite 会优先加载它并绕过网关。旧的生成文件已删除并写入 `.gitignore`。

## 数据口径

- 合约池由 `GET /api/instruments` 提供，界面按「股票池 15 + 加密池 2」分组；SOXL/SOXS 按交易所实际类型标为 `ETF`。
- 只有已收盘K线进入分析；未收盘的那根在取数时就被丢弃。
- **持仓量显示 USDT 名义额**（`openInterestValue`），不是张数。`openInterest` 是张数/币数，两者对 AAPL 差约 333 倍、对 BTC 差约 7.7 万倍。
- 资金费率为 0 时标注「交易所实际报价 0」，与「数据缺失」区分。
- 多周期共振由引擎计算（`GET /api/resonance`），前端不再自行推算。不足 220 根已收盘K线的周期显示「不足」，不参与评分。
- 每一类数据（K线 / 衍生品 / 共振）各自降级：K线失败才回落到明确标注的演示数据，衍生品失败不会清空图表。

## 图表交互

K线图是 canvas 绘制，绘图与指针命中**共用同一份几何**（`plotGeometry` 读取元素自身的内容盒）。

之前两者不一致的原因：`ResizeObserver` 量到的是 padding box（880），而命中用 `clientWidth`（864），相差 16px 导致越靠边偏得越多。现在不再用 state 保存宽度，而是在绘制时现场测量，指针命中也读同一函数。

悬停会显示该根的最高价、最低价、开盘、收盘、成交量与**时间区间**（如 `09/12 14:00 → 14:15`，按本机时区）。当可见K线超过 160 根时会按整数倍合并绘制，区间随之变为合并后的跨度。

## 模型设置与截图识别

- 「设置」页可写入 API Key、测试连通性、拉取该账号可用模型列表、把每个能力（深度研判 / 图表识别 / 日志总结 / 信号解释）切到任意 profile。
- Key 只写入 `~/.quantdesk/keys.env`（权限 600），浏览器只能读到「是否已配置」。
- 若保存的是占位符（例如从文档复制的 `sk-...`），卡片会直接显示「Key 无效」并说明原因，
  而不是等你点「测试连通」再从上游拿到一个 `Authentication Fails`。
- 「截图识别」页上传 PNG/JPEG/WebP，由声明了 `supports_vision` 的 profile 处理，结果落 `chart_analyses` 表。返回内容包括趋势、结构要点、价位、形态、可见指标，以及**「无法确认」清单**——模型不被当作行情源。
- 若 `chart_analysis` 指向纯文本模型，请求会被拒绝（409）而不是静默改发其他供应商。

## 回测与模拟交易

- 「策略回测」调用引擎的 `POST /api/backtest`，前端不再自带算法。页面可配快慢线、方向、资金、仓位、手续费、滑点、**杠杆**、**维持保证金率**，以及资金费 / 强平 / 休市空 bar 三个开关。
- 结果区分**手续费**与**资金费**（含符号）、标出强平笔数，并展示引擎声明的 `assumptions` 与数据质量（K线根数、休市空 bar 数、资金费数据点数、tickSize/qtyStep）。
- 上传过K线文件时，回测直接把浏览器里的数据发给引擎，不重复取数。
- 「交易日志」页签里是模拟账户：持仓按标记价估值，显示未实现盈亏、保证金率、距强平价百分比（<5% 红、<15% 琥珀）。开仓理由可随时改，平仓时写入不可修改的日志。
- 日志条目带内容哈希，顶部显示哈希校验结果；支持导出 JSON / CSV，导出内容含完整性报告。

## 多智能体与快速研判

「深度研判」页默认调用 `POST /api/tradingagents/run`，运行真正的官方 `TradingAgentsGraph`：

- 代币化股票和 ETF 的价格、成交量与技术指标严格使用 Bybit USDT 永续合约日线；新闻和财务工具才映射到公开参考证券代码。BTC/ETH 走只读 Hyperliquid 日线桥和市场分析师。
- 分析师报告进入多空研究员辩论，随后由交易员制定方案，再经风险辩论形成最终决策。
- 页面展示每份报告、最终评级与原始辩论状态，运行结果单独归档。
- SPCX、SKHY 均启用完整基本面分析师：合约行情分别使用 `SPCXUSDT`、`SKHYUSDT`，公开新闻与财务身份分别使用 `SPCX`、`SKHY`。

同一页面可以切换到「快速研判」，调用 `POST /api/research`：

- 把**当前图表上的K线**与额外关注点一起发给引擎，引擎据此算出价格结构，再交给 `tradingagents` 角色指向的模型。
- `tradingagents` 角色决定两种研判使用的 profile；多智能体模式把该 profile 映射为官方运行时的 provider、模型和凭据。
- 上传历史K线会进入隔离模式，不混入当前 ticker 与其他周期行情；演示数据禁止研判。
- 产出卡片直接给出**入场、止损、止盈1、止盈2**，以及引擎重算的盈亏比、单笔风险、止损/ATR 倍数与建议仓位。
- 计划自洽性由引擎判定：顺序错误、止损过近、盈亏比自报不符、仓位过大都会在卡片里列出。
- 「送到模拟盘」一键把方向、名义额与全部点位预填进模拟开仓表单，理由会写进订单备注，平仓后进入不可改日志。
- 折叠区展示全部可引用证据（键 / 值 / 来源），以及校验结果：引用键数、无法定位的数值、越权指令用语。
- 报告落库保存，页面左侧列出历史报告并标出是否通过校验。

没有配置 Key 时页面会直接说明缺哪个变量，按钮保持禁用，不会静默失败。

## 时间与超时

最慢的一次调用是研判（推理模型实测 56–145 秒）。相应设置都已放宽，否则浏览器只会看到
一个没有上下文的 `Failed to fetch`：

| 位置 | 值 |
| --- | --- |
| `vite.config.ts` 的 `/api` 代理 | 400 秒 |
| `services/research.ts` 请求超时 | 420 秒 |
| `services/llm.ts` 连通测试 | 120 秒 |
| `scripts/smoke.mjs` 等待计划卡片 | 400 秒 |

## 验证

```bash
npm run typecheck                 # tsc 全量类型检查
npm run build                     # 生产构建
npm run smoke                     # 无头浏览器冒烟
node scripts/probe-chart.mjs      # 单独的悬停对齐探针，可指定周期
```

`npm run smoke` 需要 dev server 正在运行，并会断言：两个分组、2 个 ETF 标签、17 个标的全部拿到 BYBIT 实时K线（无演示降级）、稳定态状态条为实时、4 个周期各 3 个采样点的悬停命中正确、设置页列出全部 profile 且未泄露 Key、`/api/llm/*` 代理可达、**引擎回测返回指标与口径声明**、**模拟盘表单与日志完整性报告可渲染**、无控制台错误。它复用本地已缓存的 Playwright Chromium。

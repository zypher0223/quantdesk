# 持仓浮动风险约束（风险预算的第二重绑定）

这份文档说明"风险预算"怎么从**只管入场**变成**同时管住已持仓的浮动风险**：规则、
默认值、时延约定、计数器、真实数据证据和已知缺口。改代码就要改这里。

适用范围：`engine/src/quantdesk/backtest/engine.py` 的意图分支、
`engine/src/quantdesk/strategy/cpa/defaults.py` 的参数、`engine/src/quantdesk/studies.py`
的参数透传。仍然只读本地历史，不联网、不下单、不接实盘。

---

## 1. 改动前的问题

`maxPortfolioRiskPct` 原来只在**开仓/加仓**时检查一次：用"开仓价到结构止损的距离 ×
数量"对比权益的一个比例，超了就拒绝这笔意图。这个检查的口径是**入场价**，而持仓一旦
朝着有利方向走，价格离结构止损越来越远，同一个仓位的**已承担风险**就比开仓时更大。

实测（`run_single`，本地历史，股票永续 1h、3000 根、预算 1%、CPA 默认参数）：

| 标的 | 只在入场约束（改动前） | 同时约束持仓（改动后） |
| --- | --- | --- |
| MSFTUSDT | 最高已承担风险 **234.2**（预算 100），收益 +1.01% | **186.2**，4 次减仓，收益 +0.67% |
| TSLAUSDT | **346.8**，收益 +2.52% | **326.4**，13 次减仓，收益 +2.27% |
| AMZNUSDT | 168.5，收益 **−2.54%** | 168.5（1 次减仓），收益 **−1.98%** |
| NVDAUSDT | 129.3，收益 **−2.51%** | 127.9（16 次减仓），收益 **−1.94%** |

也就是说：旧口径下"预算 1%"实际允许承担 2–3.5 倍预算的风险，因为风险是在最有利的那一刻
才长出来的。约束在两个方向都出现过效果：MSFT/TSLA 上削掉了趋势里的部分利润，AMZN/NVDA
上减少了亏损。

## 2. 规则

预算同时绑定两处，用的是同一个函数（`risk_budget_of()`），所以两处口径不会漂移：

1. **入场风险**（原有行为，未改动）：`|开仓价 − 结构止损| × 拟持仓数量 > 预算` → 拒绝
   该次 `open` / `increase`，记录 `rejected` 与原因。
2. **持仓浮动风险**（本次新增）：每根K线在**意图与结构止损都处理完之后**，按该根的
   **收盘价**重新标记 `|收盘价 − 结构止损| × 持仓数量`；超过预算就武装下一根：
   - 下一根**开盘**按 `keep = floor(预算 / |开盘价 − 止损|)`（按 `qty_step` 取整）
     减到预算内，走 `_close_partial`，`total_fees += trade.exit_fee`（开仓费在开仓时
     已经计入）；
   - 若 `keep ≤ 0`，或超出部分的名义额低于 `min_order_notional`（默认 5），则**整笔
     平仓**（理由 `risk_budget`），而不是把一笔不合规的风险留在账上；
   - 若这一根的开盘已经把风险带回预算内（价格反向、或没有可减的数量），则只作废警报，
     不下单。

### 时延约定（不引入未来数据）

触发信息是**第 i 根的收盘**，这在第 i 根结束时已经确定；成交放在**第 i+1 根的开盘**。
这与意图本身"第 i 根决策、第 i+1 根开盘成交"的规则一致，也避免"用刚看到的收盘价成交"。
代价是：从收盘越界到成交之间隔着**一根K线**，这一根里的逆向波动仍会被承担。

### 不被重复触发的三种情形

- 同一根开盘上已经有一笔 `exit` 意图要整笔平仓 → 跳过风控减仓（同一个价格上再减一次
  只是多付一笔手续费）；
- 开盘价已经越过结构失效价 → 交给结构止损处理（那种情况下止损必然在本根触发）；
- 持仓没有结构止损价 → 无从度量浮动风险，不动作（`maxRiskCarried` 保持 0）。

## 3. 参数与默认值

| 参数 | 默认 | 位置 | 说明 |
| --- | --- | --- | --- |
| `maxPortfolioRiskPct` | 2%（15m/1h/4h）、8%（1d/1w） | `cpa/defaults.py` | 预算本身，占**当时权益**的比例；入场与持仓共用 |
| `enforceOpenRisk` | `true` | `cpa/defaults.py` | 本次新增：是否用同一预算约束持仓浮动风险；关掉即回到"只管入场"，用于对比 |

`PARAMETER_VERSION` 随之从 `cpa-qd/1.1.0` 升到 `cpa-qd/1.2.0`；策略版本记录里带着
`enforceOpenRisk`，两次结果可以据此对齐参数。

引擎侧参数为 `run_backtest(..., enforce_open_risk: bool = True)`；`position_intents=None`
（默认的单仓位/事件路径）时这段代码一行都不会执行。

## 4. 结果里的字段（`data_quality.positionIntents`）

| 字段 | 含义 |
| --- | --- |
| `maxRiskCarried` | 逐根按**收盘价**标记的最大已承担风险。**语义已变**：改动前是"入场价到止损 × 数量"，现在与约束同一口径，因此"打开 vs 关闭"可直接比较 |
| `riskBudgetEnforced` | 本次是否真的在约束（既开了开关、又给了预算） |
| `riskAlerts` | 收盘标记越过预算的K线数（= 需要下一根纠正的次数；也是"一根K线时延"的暴露量） |
| `riskReductions` | 风控**减仓**次数（与意图减仓 `reduces` 分开计数） |
| `riskExits` | 风控**整笔平仓**次数（与意图离场 `exits`、结构止损 `stops` 分开） |
| `riskBudget` | 参考预算（按**初始资金**计），两个实时检查用的是当时权益 |
| `records[]` | 每次风控动作一条：`stage="risk_budget"`、`action=reduce/exit`、`status=risk_reduced/risk_exited`、`price`（成交价）、`quantity`、`positionQuantity`（减后仓位）、`riskBudget`（当时预算）、`reason`（含越界风险与预算的数值） |

同时会写一条中文 `warnings`，说明触发次数与"下一根开盘执行"的时延。

## 5. 测试与证据

`engine/tests/test_cpa_positions.py::CarriedRiskTests`（8 条，含数值断言）：

- 越界的那根收盘 → 下一根开盘成交：断言 `index` 与 `price` 精确等于下一根开盘价；
- 减仓后 `|成交价 − 止损| × 减后数量 ≤ 该条记录里的 riskBudget`（逐条断言，多空各一）；
- 超出部分太小 → 整笔平仓（`riskExits=1`、`positionQuantity=0`、`trades` 里只有平仓那一笔）；
- 同一根开盘已有 `exit` → 不减仓（`riskReductions=0`、`riskExits=0`，离场仍以原价成交）；
- 没有预算 / 关掉开关 → 与旧行为逐位一致（权益、费用、成交笔数相同）；
- 事件路径（`signal_events`）下加了预算与开关也不改变任何数字；
- CPA 参数默认 `true`，版本升到 `cpa-qd/1.2.0`，`studies.py` 的透传有源码级守卫。

回归：`engine/.venv/bin/python -m pytest tests -q` → 1151 passed / 2 skipped；
`DefaultParityTests` 的基线数字（`final_equity 10061.394701`、`total_fees 367.497796`、
30 笔、首笔 `105.6528 → 113.943`）保持逐位一致。

真实数据样本（`run_single`，本地历史，只读；股票永续 1h）：

| 场景 | 关闭约束 | 打开约束 |
| --- | --- | --- |
| **默认 2%**、600 根、10 个可跑标的 | — | 8 个**完全一致**（0 次触发）；AAPL 收益 +1.47%→+1.33%（3 次越界、2 次减仓），TSLA −0.44%→−0.45%（4 次越界、4 次减仓） |
| 预算 1%、3000 根 | MSFT 234.2 / +1.01%，TSLA 346.8 / +2.52%，AMZN 168.5 / −2.54%，NVDA 129.3 / −2.51% | MSFT 186.2 / +0.67%，TSLA 326.4 / +2.27%，AMZN 168.5 / −1.98%，NVDA 127.9 / −1.94% |
| 预算 0.5%、600 根 | MSFT 62.4 / +0.18% | MSFT 61.3 / +0.18%（2 次越界、1 次减仓） |

结论：默认预算下多数标的**没有任何变化**，只有那些跑出远超止损距离的行情才会被削；
预算收紧后约束稳定生效，方向可正可负（有削利润、也有减亏损）。

注意：这些数字取自本文件写下时的检测器版本。CPA 的入场规则仍在演进，规则一变，
意图序列与这些数值都会变，重新取证即可（上表口径已写全：`run_single` + `bars` + 预算）。

## 6. 已知缺口（明确不做/做不到的）

1. **一根K线的时延**：纠正发生在越界之后的下一根开盘，所以 `maxRiskCarried` 仍可能超过
   预算，超出幅度 = 那一根里价格逆向走了多少。真实数据（1% 预算、股票 1h、3000 根）
   观察到 326.4 对 100（TSLA，无约束时 346.8）与 186.2 对 100（MSFT，无约束时 234.2）。
   想做更紧只能按不利极值在**根内**触发，那等于给所有持仓加一条按价格的隐形止损，属于
   另一个决定，本次没有做。
2. **"越界"不等于"减仓"**：开盘时价格可能已经把风险带回预算内（`keep ≥ 持仓`），此时只作废
   警报、不下单，所以 `riskAlerts` 可以大于 `riskReductions + riskExits`（真实数据里 AAPL
   与 META 各出现过 1 次越界 0 次动作）。
3. **逐根复核会带来换手**：单边行情里"价格每涨一点、风险就多一点"，会连续多根小幅减仓
   （实测 NVDA 1% 预算出现 16 次减仓、TSLA 13 次）。绝对手数与成本都在 `orderFees` /
   `total_fees` 里，没有被隐藏。
4. **没有结构止损就没有浮动风险**：不变量缺失时不做任何事，这类持仓（`stop_price=None`）
   完全不受预算约束。
5. **单仓位账本**：约束只作用于当前这一个持仓；组合层（多标的、相关性、总敞口）仍未建模。
6. **仍不接实盘**：这一层只改回测/验证的模拟结果，不产生任何真实订单，也不改任何账户。
7. `riskBudget` 字段本身仍按**初始资金**计算（历史字段，保持不动），两个实时检查按当时
   权益计算；两者只有在权益偏离初始资金时才会不同，记录里的 `riskBudget` 是当时值。
